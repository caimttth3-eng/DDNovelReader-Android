版本为 **1.3.22（56）**。最终完整套件、Analyze、本地离线构建、固定签名、独立验签、SDK 全树核对、接收及收尾均已完成。未安装真机，不以主机验证替代 vivo OriginOS 7 实测。

## 修改

段距只显示 **无、一档、二档、三档**，保存整数 0..3，默认二档。实际距离由当前字体、文字缩放、真实原生行距及正文高度计算，不再展示字号倍数。同一排版几何下四档共用行数 K，额外段距分别为 `0、Smax/3、2Smax/3、Smax`。一次几何内所有段界使用相同距离，不逐页拉伸；改变字体、行距或屏高会重新计算。旧零段距保留“无”，旧 .5/1 倍映射三档，其他旧值及缺失值回到二档；已有合法整数档位继续保留。

用户重新明确半字号波动必须是硬约束后，生产取消 1.3.21 的宽区间回退。字体测量从准备 worker 收集的全书唯一 grapheme 库存出发，在 UI isolate 对正常、粗体及跨段 strut 测得实际基线步进 P 和字形上下包络，P 不直接等于字号乘行高。测量预算预留 0.5px，并累计每个内部行距的上下误差。库存加有限上下文探测不能单独证明所有真实排版；显示前的原生实际页验收是最终约束门。

`ReaderSpacingPolicy` 在该包络和基线区间前提成立时选择 K，使其最多比最短字形／最小行距下的真实最大容量少一行，并为四档给出同一个全局占用区间。不能满足这一容量条件、字形包络过宽或字体几何不支持时，明确提示用户调整字体、字号或行距，不偷偷放宽区间，也不靠主动制造一行页达标。真实矮屏只能容纳一行时允许 K=1，四档额外段距都为零。

`ReaderPagePlanner.fixedRows` 从当前原文边界向前、向后都每 K 行分组，不以截取行表的起点顺排后取末尾碎片。这修正了修改段距后向前翻出现巨大余白的路径，包括实际可容约 12 行却只显示两行前缀碎片的问题；同一套行数、全局预算与真实行表用于两个方向，不再另接镜像分支。最近四份几何切片缓存的补偿逻辑已移除。旧严格求解器、`solveReadable` 及镜像转换仅留作数值研究和独立服务测试，不再决定生产页面。

完整 K 行的页面，包括真实书首、书尾，均必须通过全局占用区间。只有真实书首／书尾不足 K 行的源文片段可以豁免；临时测量窗口的不足 K 行片段绝不发布。物理章节仍不是强制分页边界，原文标题仍同正文字号和行距，仅加粗居中，技术切块不生成“第 N 节”。

普通实际页要求首字形行贴近页顶，实际末字形底边在全局占用区间内，额外原生验收公差为 ±0.1px。预算幅宽先收至 `F/2−0.5`，因此通过验收的稳定普通页底余白总波动最多为 `F/2−0.3`，仍小于用户要求的半字号。初始恢复、过滤或几何重排在撤去遮罩前也执行实际页校验；不合格时保持拒绝状态。自由上下滚动不作分页余白承诺，真实源端短页也不计入普通页极差。

同时修正正常分页归位对最接近页顶的真实字形行的选择，以及混合字体远锚点通过全行安全范围并集定位，避免偏移 20000 错落到 20005。保留过滤级别交错、完整源文覆盖、前后可逆、朗读起点与裁切一致的检查。

## 数学依据与限制

先前“固定 .25 倍字号也普遍支持半字号波动”的推断已被反例纠正。固定 F=39、P=1.2F、S=.25F、H=760 时，长段允许少一行的余白集合为 `{19,65.8}`，单行段集合为 `{42.4,98.95}`，最近距离 23.4 大于半字号 19.5。即使把 S 取成 P，共同格点也不能保证连续分页；另有两端豁免仍只能产生一行普通页的反例。它们否定的是任意预设大段距都可兼顾硬区间与容量的承诺，不是修改原文或动态拉伸间距的理由。

新策略先按几何预算选择固定 S，再固定 K，而不是强迫任意旧 S 适配页面。任意段落分布都由每页 `0..K−1` 个内部段界覆盖，条件和推导见 [1.3.22 数学附录](../reader-layout-audit-2026-11-21.md)。该充分条件依赖共同基线步进区间和有效字形包络；实际页验收继续拦截上下文成形、回退字体或宿主排版差异。主机测试不代替 vivo OriginOS 7 真机验收。

库存测量优化采用正常／粗体各一次完整 UTF-16 selection 的 tight 原始 run boxes，不先把 run 合并成一张大框，也不逐 grapheme 重复原生查询。[Flutter 对 tight 的定义](https://api.flutter.dev/flutter/dart-ui/BoxHeightStyle.html)是保留各 run 高度，区别于 max 的全行统一高度；[完整选择规则](https://api.flutter.dev/flutter/painting/TextPainter/getBoxesForSelection.html)还要求多 code unit 字形完整落入选择范围。这减少逐项查询成本，不增加对未测上下文的证明力。最终独立逐字形参考验证二者包络一致，完整库存的选择查询恒为两次；同一几何切档复用字体测量。

并行完整套件中的 Windows 字体研究：5081／9081 个唯一 grapheme，当前路径首次约 2.07／1.66 秒、热测约 22.6／32.2 毫秒；随后执行的旧逐项参考约 87.4／150.6 毫秒，查询分别 10164／18164 次。首次字体加载、执行次序和并行竞争影响计时，参考省略部分 profile 检查，不能把数字直接解释成手机加载时延或严格冷启动加速比。
