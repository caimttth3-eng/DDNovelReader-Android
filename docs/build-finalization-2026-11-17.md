# 构建收尾入口适配（2026-11-17）

本轮只改现有入口和参考资料归属；没有真实编译、下载工具、触发 Actions、远程发布或设备操作。

## 实际入口与顺序

- `.github/workflows/build-apk.yml`：构建 → 签名/校验 → 上传分析与 APK → **最后**仅按字节相同确认后清除两个输出位置的重复 APK。上传未成功时不执行这项清理；清理异常保留警告，不覆盖构建结果。交付目录、UI 预览、独立符号、Flutter/Gradle 依赖和增量不删。私有临时签名文件仍按原安全释放协议单独清除。
- `.github/workflows/publish-release.yml`：固定 v1.2.26 的原有流程验证、上传并核远端资产成功后，最后清四个已消费下载输入；失败不执行收尾，未知文件和预览不删。未修改固定发布脚本或其历史输入身份。
- `scripts/LocalApk.ps1`：同步原生验签返回 → staging 全文件原字节核对/完整包校验 → 原子移动版本目录 → 复核当前选择 → **最外层成功收尾**。在现有独占锁内复核占用后退役旧包；只删除已交付的重复文件与逐项核实的两种下载 ZIP，不扫描其他目录。
- 同一入口的 `KeepArtifacts` 延后清理以交接父消费者；其自然结清后用 `Finalize`，重新核当前完整包并重试 `cleanupPending`。记录实际移除路径、数量、字节；不创建 Job/provider、登记表、后台清理服务或第二套生命周期机制。
- 失败只清本次自有、已经结束复制的 staging，保留可重试输入和旧可用包；原子移动后的复核失败会先退回 staging、恢复旧选择。占用/回退阻塞会保留明确警告，不杀进程。父流程 `KeepArtifacts` 保留的失败 staging 仍由父 owner 结清，未冒称已清理。
